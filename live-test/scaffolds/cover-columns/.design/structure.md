# あさのび 画面の構造

あさのびの各画面の組み方（どこで幅が止まるか、何がどの順に並ぶか、幅が狭まったとき各部分がどうなるか）と、点検で確かめる画面の大きさの決めごと。画面を作る・直すときは人もエージェントもこれに合わせる。値と色は `.design/declaration.md`、文字列は `.design/lexicon.md` にある

- 作成: 2026-11-04、design-discipline の `fix`（修繕 R24）

## checked sizes（確かめる大きさ）

| 大きさ | 理由 |
|---|---|
| 360 × 548 | 一番狭い幅。README の「利用者の半分はスマートフォン」から、CSS 幅 360px の Android 端末を下限にした。高さは小さい iPhone（SE 第3世代、画面 375 × 667）の Safari で上下のツールバーが出ている状態の約 548px を下限に取った。どちらも端末の公表値からの計算で、実機で測っていない |
| 1920 × 900 | 一番広い幅。README の「残りはノート PC」から、1920 × 1080 の画面を 100% の拡大率で使い、タスクバー（48px）と Chrome のタブ・アドレスバー・ブックマークバー（約 130px）が高さを取った状態。これも計算で、実機で測っていない |

## 表紙

### structure

幅 1080px 未満は flow、1080px 以上は 2 columns。幅を止める値と切り替える幅の理由は、決めごとの maximum content width

- 1080px 未満（flow）: 中身は縦に読む順に積み、幅は割らない。幅を止めるのは中央に置いた列で、最大 40rem（640px）。列の左右の内側の余白は 24px（3 単位）
- 1080px 以上（2 columns）: 左の列に誘いと記録の紙、右の列にきょうのメニュー。各列は最大 37rem（592px）、列の間は 64px（8 単位）、二つの列と間を合わせて中央に置き、全体は最大 81rem（1296px、左右の余白 24px を含む）。上の段は左の列の見出し・説明・「はじめる」だけで、右の列は空ける。右の列のメニューは、記録の紙の上端と同じ高さから始まる（下の段に記録の紙とメニューが横に並ぶ）。上の帯も同じ 81rem に広がり、ロゴは左の列の左端、「使い方」の右端は右の列の右端に揃う
- 一番広い 1920 幅で一本の列の外の幅が運ぶもの: 右に並べたきょうのメニュー（a region beside another）。描くものは x 336〜1584 の 1248px で、画面の幅の半分（960px）を超える。外の左右 312px ずつは台紙の地。左の列の中では signature の参加票が記録の紙の内側いっぱいに広がり（1 列約 80px）、はんこが 48px になる（2026-11-05 の `fix` の K02、2026-11-06 の `fix` の M01）

### arrangement（並び）

| 順 | 部分 | 中身 |
|---|---|---|
| 1 | 上の帯 | 左にロゴ「あさのび」、右に「使い方」 |
| 2 | 誘い | 見出し（display の段）、説明の一文、「はじめる」（主の操作）、記録の紙（週の見出し、今週の参加票、その下の一行） |
| 3 | きょうのメニュー | 区切りの見出し、メニューの紙（ポーズ名と秒数の行）、紙の下に「ほぐす所」と「道具」の行 |

- 何が並びを決めたか: 最初に「きょうのメニューと所要時間」と開始の操作を置く形は Bend の最初の画面から（`.design/record.md` の採った形）。記録を週の升目の紙にするのは郵政博物館の参加票と決めごとの signature から。記録の紙を「はじめる」のすぐ下に置くのは、決めごとの signature が両方の確かめる大きさで最初に見える範囲に入ることを求めるため（2026-11-04 の `fix` の I03。それまでは並びの 4 番目「あなたの記録」で、見える範囲の外だった）。「はじめる」を押してはんこを一つ増やす、という読み順にもなる。足元の帯は置かない（運ぶ情報が無い。修繕 R08）
- 1080px 以上で誘いとメニューを横に並べるのは、「はじめる」を押す前にメニューを読む判断を、ノート PC の幅で送らずにできるようにするため（決めごとの maximum content width）。読む順は見出し → 説明 → 「はじめる」→ 記録の紙 → メニュー。誘いが左なのは、日本語の横組みで読み始める側だから
- メニューを見出しの高さではなく記録の紙の高さから始める理由: 見出しの高さから始めると、メニューの行が見出しと同じ高さで画面の右半分を占め、見出しと並ぶ二つ目の中心に見えた。参加票より縦に長いメニューが、読む順で後に来るのに目立つ順で先に来た（2026-11-06 の `fix` の最後の全点検 2 回目の見直し役の指摘 1。M01 の変更が生んだずれとして直した）。上の段を見出し・説明・「はじめる」だけにすると、画面の中心は見出しの一つになり、その下で参加票とメニューが並ぶ。1920 × 900 ではメニューの最後の行と「道具」の行まで送らずに見える（`.design/captures/2026-11-06-fix-pass4b/cover-populated-1920x900-view.png`）
- 主の操作「はじめる」の位置: 360 × 548 では最初に見える範囲の下半分に入り、親指が届く。1920 幅では見出しと説明を読んだ順の直後に来る
- 360 × 548 で参加票の升目の下端までを最初に見える範囲に入れるため、600px 未満では誘いの上の余白を 24px、見出しの下を 16px、説明の下を 24px にする。「はじめる」と記録の紙の間は 24px
- 紙（カード）はメニューと記録の二枚だけ。誘いの部分は台紙の上に直接置く。紙は決めごとの elevation の flat（影なし、1px の ai-rule の縁、角は card 8px）。1080px 以上では記録の紙の一枚だけにし、メニューは紙にしない（下の「メニューの紙」）
- 密度: この画面の仕事は「きょう始めるか」の一つの判断。メニューは一目で読める 5 行に留め、行の間は 16px ずつ空けて詰めない

### 端と間隔

- 左端は列の内側の一本（列の左 + 24px）。上の帯、見出し、説明、ボタン、区切りの見出し、紙の外側、「ほぐす所」の行はすべてここに揃える。1080px 以上では列ごとに一本: 左の列はロゴ、見出し、説明、ボタン、記録の紙の外側。右の列は区切りの見出し、メニューの行の文字と罫の左端、「ほぐす所」の行
- 紙の中の文字は紙の縁から 16px 内側の二本目の端に揃える。二本目は「刷った枠の中に書く」ことを示すための端
- 間隔: 部分の中の間は 8〜32px、部分と部分の間は 64px 以上。区切りの見出しと紙の間 16px、紙と「ほぐす所」の間 16px、「ほぐす所」と「道具」の間 8px、「はじめる」と記録の紙の間 24px

### メニューの紙

- 行の並び: 左にポーズ名（item の段）、右に秒数（small の段、ai-70、右揃え）。行と行の間に 1px の ai-rule の罫。罫は行を分けるためのもの
- 秒数は右端を揃えた列。書体に等幅の数字が無いので、右揃えで桁を合わせる（決めごとの figures）
- 1080px 以上: 紙にせず、台紙の上に行を置く。白い面、縁、角丸、紙の内側の 16px を外し、一行目の上と最後の行の下にも 1px の ai-rule の罫を引く。文字は右の列の左端から始まる。理由: 横に並ぶと、メニューの紙（592 × 304px）が参加票の紙（592 × 216px）と同じ幅の白い紙として同じ高さに並び、参加票より大きく目を取った。読む順（「はじめる」→ 参加票 → メニュー）と目立つ順が逆になり、見出しとメニューの紙の二つが画面の中心に見えた（2026-11-06 の `fix` の最後の全点検の見直し役の指摘 3。M01 の変更が生んだずれとして直した）。白い紙を参加票の一枚にすると、参加票が画面でただ一枚の紙になる

### 記録の紙

- 上から: 週の見出し（今週と日付の範囲、small の段。紙の題として見出しの要素にする）、参加票の升目、状態の一行。紙の中に操作は置かない。空とはじめての状態でも、すぐ上の「はじめる」が始める操作になる（I03 で、紙の中の副の「はじめる」を外した。24px 上に同じ名前の操作が二つ並ぶため）
- 参加票: 月〜日の 7 列。各列は上に曜日の升、下にはんこの升。升の罫は 1px の ai（藍）で、隣どうしが一本の罫を共有して直角に交わる。紙の縁（ai-rule）より濃く、記録の紙の中で一番強い線（2026-11-06 の `fix` の M02）。列は記録の紙の内側を 7 等分する（1920 幅で約 80px、360 幅で約 40px）、升は正方形、角丸なし
- はんこ: 押した日の升の中央に、朱の円の縁と「済」一字の印影。升の幅が 64px 未満で 32px、64px 以上で 48px。描き方は `.design/style-system.md`
- 状態ごとの中身

| 状態 | 参加票 | 一行 |
|---|---|---|
| 記録あり（今週も） | 押した日にはんこ | これまでの回数と分 |
| 空（記録はあるが今週はゼロ） | はんこなし | 今週はまだ無いことと、これまでの回数と分 |
| はじめて（記録が一つも無い） | はんこなし | 記録がまだ無いことと、終えた日にはんこが押されること |
| 読めない | 出さない（週の見出しは出す） | 読み込めなかったことと、原因ごとの次にすること（保存が止められている / 保存された記録の形が壊れている） |

### reflow（幅が狭まったとき）

| 部分 | 狭まったとき |
|---|---|
| 誘いと記録の紙、きょうのメニュー（二つの部分） | 1080px 以上で横に並び、二つの列が同じ幅で縮む（1080px で各 484px。決めごとの値からの計算で、その幅では測っていない）。1080px 未満で縦に積み、誘いと記録の紙の下にメニューが来る |
| 上の帯 | 一行のまま。ロゴは左、「使い方」は右に残る |
| 見出し | 「、」のあとで折り返す。その半分が一行に入らないときだけ、半分の中の語の切れ目（からだを / のばして、きょうを / はじめる）で折る。語の途中では折らない。600px 未満で display の段が 2.5 倍から 2 倍になる |
| 説明・状態の一行・使い方の文 | 折り返す。行の数に上限は無い |
| メニューの行 | 1080px 以上では紙ではなく台紙の上の行、1080px 未満で紙の中の行（上の「メニューの紙」）。ポーズ名が名前の欄の中で折り返す。区切れない長い語も欄の幅で折る。秒数は折り返さず右端に残る |
| 参加票 | 7 列のまま一行。列が紙の内側を等分する（360px 幅で約 40px、1920 幅で約 80px）。升の幅が 64px を下回るとはんこは 48px から 32px になり、それより小さくはしない |
| ボタン | 文字は一行のまま。ボタンの幅は文字に合わせる |

隠す部分は無い

### overflow（文字があふれたとき）

すべて折り返す。切り詰め（…）とスクロールは使わない。秒数と回数の数字だけは折り返さない

### 戻る

| 段 | 戻るを押すと | 戻ってこられる必要 | どういう行き先か |
|---|---|---|---|
| 表紙 | 来たところ（ブラウザの前のページ）へ出る。製品は表紙の下に履歴を書かない | ある。ロゴと URL で何度でも来られる | 製品の入口、アドレスは `/` |
| 「はじめる」のあと | 表紙と同じ。メニューへ移るのはページの中の移動で、履歴を足さない | — | 表紙の中の位置 |

- 「はじめる」のあと、1080px 以上: メニューはすでに横に見えているので、画面は送れる分だけ送る（1920 × 900 では送れる長さが無く動かない）。フォーカスを受けたメニューの見出しに、キーボードのときと同じ 3px の ai の枠を、ポインターで押したときも出す。移った先を示すものが、画面が動かないこの幅ではこの枠だけになるため

## 使い方のシート

### structure

表紙の上に重ねる sheet（一段だけ）。下の幕は台紙を暗くし、押すと閉じる。シートは画面の下端に付き、幅は表紙の列と同じ最大 40rem で中央に置く。1080px 未満では、中の左端は表紙の列の左端と揃う（シートの内側の余白 24px）。1080px 以上では表紙が二つの列になるので、シートは画面の中央に置いたまま、中の左端はどちらの列の端とも揃えない。下の表紙は幕で暗くなっていて、シートだけを読む。上の二つの角だけ card 8px

### arrangement

上から: 題（title の段）、本文、「閉じる」。題は開いたボタンと同じ「使い方」で、押したものと開いたものが同じ名前になる。本文が一つで手順が無いので sheet にした（navigation の容器の表）

### なぜブラウザの `<dialog>` を使わないか

ブラウザの `<dialog>` を `showModal()` で開くと、HTML の仕様（WHATWG HTML Living Standard の dialog 要素の節）では、その時点でシートの外の要素がすべて操作を受けなくなる。開いた直後の 500ms は、速い 2 度押しの 2 回目が「使い方」そのものに当たるよう、幕が押し込みを通している（2026-11-04 の `fix` の I06）。`showModal()` ではこの 2 回目が幕に当たる。だからシートは `role="dialog"` と `aria-modal`、表紙の要素の `inert`、フォーカスの出し入れを `app.js` で作っている。Escape で閉じるのは `app.js` の keydown で「閉じる」と同じ道（履歴を一つ戻る）にした（2026-11-05 の `fix` の K05）。仕様の読み取りは文書からで、`showModal()` の版を作って測ってはいない

### reflow

本文が折り返す。シートの高さは中身に合わせる。幅が 40rem より狭いときは画面の幅いっぱい

### 戻る

| 段 | 戻るを押すと | 戻ってこられる必要 | どういう行き先か |
|---|---|---|---|
| 使い方のシート | シートが閉じ、開く前の表紙の同じ位置に戻る。「閉じる」と幕を押したときも同じく履歴を一つ戻る | ある。「使い方」でまた開ける。進むでも開く | アドレスを持たない重ね。開くときに同じ URL のまま履歴を一つ足す。再読み込みしても開いた姿で戻る |
