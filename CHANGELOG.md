# Changelog

What a fresh copy of `skills/` gets you, newest first. Install is the same at every entry:
copy the five directories in, replacing the ones you have.

## 2026-11-05

The declaration names where your product is bold: the world outside its category whose look it
borrows, and the one element it is remembered by, which sits where a reader sees it before
scrolling on at least one screen. At least one of the references studied comes from outside the
product's category. A color may fill a large surface without becoming a second accent, the
display size states how far it jumps from body text and why, and text may cross artwork once which
sits in front is decided. People drawn as a generator's default are rejected. `init` shows the
look as a whole first. On a product whose declaration was written before this, run `init` once
with a browser to add the two entries.

A title, a heading, or a name breaks between words, and in Japanese between phrases; neither it nor
a short text standing on its own ends on a last line of one character, punctuation not counted. The
structure says what a wide display's width past one column is for, and a column centered with bare
background either side is counted as a default, lifted only where the declaration's recorded
exceptions name it. The signature is read for whether it is what the eye reaches after the primary
action, and the visual concept for whether it reaches the screen in more than its colors.

Where the session can start a second agent on a smaller model, that agent writes the scripts that
take counts and the session reads them back; an inspection script runs one rule file's counts
alone, so a `fix` pass rechecks only what it changed; every step a script waits on has a time
limit, and a method that hung is written down so no later script uses it. On the web, the skill
now carries a tested runner, `runner/web/run.mjs`, which needs Node 22 or later and Chrome: a run
writes the product's configuration for it instead of a script of its own. Each entry says its first
line before any tool call, and writes every line in your language.

## 2026-11-02

Screens are checked at the sizes their readers are left with: the widest and narrowest width,
each at the shortest height a reader meets there — a phone with the browser's bars showing, a
laptop the system scales — each written into the structure with its reason. At those sizes a
press on each control is read for whether it lands on the control, and two controls' press
areas may not overlap. Text over a background that moves is measured at its worst moment, and a
timer that unlocks or moves on stops when what it measures is paused.

Back closes whatever covers the screen, and nothing closes or moves on without the reader. A
mark meant for the eye is hidden from the screen reader, a phrase reaches it as one, and no
line opens with a closing bracket or ends a title on one character. Type sizes and dimming are
derived from the distance the text is read at, the larger step taken where it leaves a choice.

`inspect` reads every screen the product has, names the capture behind each pass, keeps the
scripts that take counts, and takes every count its own tools can. `inspect` and `fix` end in a
fixed order: the repairs heaviest first, then what only you can give, what was not measured and
how you could measure it on your own device, and the next command. `fix` repairs or undoes what
its own changes broke. Each entry speaks your language from its first line, said before it
writes any file.

Glowing type and a border around text that is only read are named among the defaults that
arrive unasked, and `inspect` counts text set with a glow unless the declaration records why.

## 2026-10-02

Two families of one classification that split one role by writing system — one setting the Latin
letters and figures, one the Japanese, say — are one family wherever the skill counts families,
declared as one of the one or two with the writing system each sets. Before, `rules/tokens.md`
counted them as two sans families sharing a classification and sent the pair to the recorded
exceptions. In the flow the pair counts as one only while no character is set in two of them; a
figure set in one family in headings and in the other in body text makes them two.

More rules, each on a decision a generated screen skips. A recorded exception now names
where the default goes, and the same default anywhere else is counted as if no exception were
written. A row of the same things tilted, fanned, or set in perspective is on the list of defaults
that arrive unasked, and the decorative-element check asks what the tilt carries. A word standing
in for a figure the brief supplies — many, thousands — is counted. A photograph the product ships
is held to the declared palette. A string that restates another on the same screen is counted,
and a second language shipped as texture is a recorded choice. The answers to the three
questions go through the AskUserQuestion tool where it exists, as numbered lines where it does
not, and an answer that needs words is followed by one fixed line asking for them. The
placeholder note under the declaration is put only where a value is a placeholder. Inside the
tool, each answer's text is carried in full and in the question's register. Everything said to
the person is in the person's language, and the study's captures and script live under
`.design/`, never outside the workspace. Three more fixed texts: when frontend-design or the skill
itself is missing, when screen work arrives with no declaration, and when `init` has nothing left
to do. `init` run again keeps what the person wrote. The marks on the repair list are said in the
person's words. Forcing a loading state never edits the product's code. `init` run again
with a browser studies the sites a first run skipped and puts the declaration question again.
Everything the session says to the person — the questions and what is said around them — keeps
to the person's words and to the courtesy owed to someone just met. `init` opens with a fixed
line and tries to start a browser itself before asking for one; the browser question asks
whether to study reference sites first. The answers to the questions are labeled by what the
person gets, and what holds under every answer sits below them. The texts put to the person
speak as one person to another — I and you — and name things concretely.

What you see changed, from runs on a Japanese two-page product. The one line the README asks you to
put in the project's `CLAUDE.md` now names your language and its polite form too: one long run
drifted into English without it, another into plain form. When you change a value before saving,
`init` shows the whole declaration again — your value in, anything derived from it derived again and
marked — before it asks again; before, one run named the changes in a line and asked. When you name
a file or a section to save the decisions in that does not exist yet, `init` creates it and says so
in the question, instead of asking whether it may. When you save the decisions somewhere other than
`.design/declaration.md`, `.design/record.md` names the place and every entry reads the declaration
from there; before, nothing said where a later run should look. Save as shown saves to the place you
chose before, where you chose one. `inspect` names what it could not take beside the list. `fix` run
with no repair list in the record runs the Inspections first instead of asking, and what its final
run finds new goes to the record for the next `inspect`.

Counts added or corrected from the same runs. `rules/anti-slop.md` counts rendered text against the
declared type-scale steps, the count `rules/tokens.md` had pointed at without its existing, and its
studied-references count now holds that one reference was walked as a running flow.
`rules/motion.md` counts motion running on a spring or a curve the declaration does not name, the
other count `rules/tokens.md` had pointed at. `rules/states.md` names the four long-content captures
in its count, so a skipped one shows as missing; counts text that stays the same size when the
platform's text size is raised; and reads a web tap target with the spacing exception its criterion
carries. `rules/forms.md` says how a headless browser is made to draw its own validation messages.
`rules/navigation.md` no longer asks for history beneath a deep link on every platform: the way into
the product is history where the product owns the stack and a visible link to the parent where it
does not, and an entry written into a history the product does not own — the browser's — is counted.
The last two lines of `rules/review.md`'s count — code changes tied to no repair, files written
outside `.design/` and the code — are read by every run against itself, `init` and `inspect`
included; before, only a run that held a fix pass read the first, and nothing read the second. The
typeface entry's stand-in for a family that loads after first draw is stated for every platform, not
only the web.

One more home: `.design/harness/` holds a browser's working files while a pass runs, removed when it
ends.

## 2026-09-28

First release. The design-discipline skill: eleven rule files, each carrying an Inspection —
counts that return a number and checks answered in a sentence — with the four entry commands
beside it (`init`, `review`, `inspect`, `fix`) and NOTICE holding the provenance of every
threshold. `init` derives the declaration from the subject and asks once where it lives; `fix`
and `review` ask once how far repairs may go on a product that already has screens. The README
shows seven pages built from one prompt each, the prompts verbatim, and what each run left open.
