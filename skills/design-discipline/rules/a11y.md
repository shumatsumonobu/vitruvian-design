# Accessibility

A screen that works only for the reader who sees all of it, hears none of it, and operates it
with a finger is a screen that works for one configuration of reader. The rest arrive by
screen reader, by keyboard, by voice, by switch — and none of them is an edge case to handle
later, because the interface either carries its meaning through their channel or it carries
nothing.

Several pieces of this floor already live where their subject lives, and they are counted
there, not here: contrast ratios, tap targets, visible keyboard focus, and enlarged text in
states.md; reduce motion, and touch or sound never being the only channel, in motion.md; a
placeholder never standing in for a label in forms.md. This file owns what remains: names,
images, color, focus, the keyboard, announcements, and hover.

## Every control has a name

Everything that can be operated carries an accessible name, and a control that shows only an
icon declares one. An unnamed icon control reads as "button" to a screen reader — the reader
is told they can press something and not what it does, which is worse than silence.

Where a control shows a visible label, the accessible name contains it. A reader operating by
voice says the words they can see; a name missing those words makes the visible label a lie.

## Images either say something or say nothing

An image that carries information carries a description of what it shows. An image that
decorates is hidden from the accessibility tree entirely, so it costs the listening reader
nothing. The defect is the middle ground: an image exposed to the tree with a filename or
nothing where the description should be.

Artwork — generated or drawn in code — follows the same split. Art serving an empty state usually informs — its
one line names the cause, per states.md — while art that fills space decorates and gets
hidden. assets.md decides what the artwork is; this file decides what it tells the tree.

## Color is never the only carrier

Wherever color means something — an error turning a border red, a selected item tinted, one
chart series against another — a second channel carries the same meaning: a shape, an icon, a
label, a weight. A meaning that arrives only through hue does not arrive for a reader who
cannot distinguish it, and it degrades for everyone in bad light.

This is not a ban on color meaning things. It is a ban on color meaning them alone.

## Focus goes in, and comes back

When a modal, a sheet, or a full-screen takeover opens, focus moves into it. While it stays open, focus stays inside —
tabbing does not wander into the dimmed surface behind it. When it closes, focus returns to
the control that opened it, so the keyboard reader resumes where they left off rather than at
the top of the document.

Focus order follows visual order, the same rule the movement order in forms.md applies to
fields, extended to everything focusable on the screen.

## The keyboard can do what the pointer can do

Every operation a pointer can perform, the keyboard can perform: reach it, activate it, and
where it holds a value, change it. The environment's supplied controls satisfy this on their
own, which is one more reason navigation.md bans replicas — a rebuilt dropdown is usually a
dropdown the keyboard cannot open.

## Results are announced

states.md has the interface reflect an action at once and reconcile behind it. The visible
reader watches that happen; the listening reader hears nothing unless the outcome is
announced. A submission confirmed, an item deleted, a loud rollback after a failed
reconciliation — each is announced through the environment's mechanism for it, not rendered
silently into a region the screen reader has already passed.

## Hover is a hint, not a door

Nothing essential appears only on hover. A row action that materializes when the pointer
arrives does not exist on a touch screen, and does not exist for a keyboard reader either.
Hover may add a preview or an emphasis; the operation itself stays reachable without it.

## Inspection

Nothing here can be answered from the source alone. The checks below are the walk; run them
on the running screen.

### The count

- Operable controls with no accessible name: 0.
- Icon-only controls whose declared name does not say what the control does: 0.
- Controls whose accessible name does not contain their visible label: 0.
- Informative images or depicted objects with no description, and decorative ones exposed to the
  tree: 0.
- Meanings carried by color alone: 0.
- Modals, sheets, and full-screen takeovers that open without taking focus, let it escape while
  open, or fail to return it on close: 0.
- Operations reachable by pointer but not by keyboard: 0.
- Focusable elements reached in an order that differs from the visual order: 0.
- Outcomes rendered visually with no announcement to the accessibility layer, counting only
  outcomes of the reader's own actions: 0.
- Operations reachable only through hover: 0.

### The checks

- The screen-reader walk. Turn on the platform's screen reader and traverse the main flow
  once. Write down what was read, in the order it was read, and name every stop where the
  reading did not match what the screen shows.
- The keyboard walk. Put the pointer away and run the same flow. Write down where you could
  not reach, could not activate, or could not leave.
- The name table. List every icon-only control on the screen beside its accessible name, one
  line each.

## Platform notes

- How a name, a hidden decoration, or an announcement is declared differs by environment — an
  attribute in web markup, a label property on a native view, a live region against an
  accessibility notification. The rule is that each is declared, not how.
- Every platform this skill covers ships its screen reader with the operating system, and the
  browser reads the same tree the markup declares. There is nothing to install; the walk costs
  one setting.
- Keyboard reachability is a browser default on the web until custom widgets break it, and a
  first-class citizen on desktop. On touch platforms the same tree serves switch access and
  voice control, so the walk still pays for itself even where no keyboard ships in the box.
